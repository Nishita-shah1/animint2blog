Community bonding

Polygon holes, origin branches, and the first CI lessons

2026-05-01 – 2026-05-24

Outcome

Community bonding started with work I had already opened in April: support for the subgroup aesthetic in geom_polygon() so polygons with holes render correctly. That matters for isoband contour polygons used in Hi-C genomic visualizations.

The first implementation spanned three layers: the R compiler (geom-polygon.r, geom-.r) and the JS renderer (animint.js), using GeoJSON Polygon format with fill-rule: evenodd for transparent holes. I wrote 17 tests covering compiler, renderer, and interactive cases.

Context

On 7 May I opened issue #322 as my public GSoC log. Toby invited me to the animint developers team and asked that future PRs come from branches in the org, not my fork. He also pointed me at animint-blog for write-ups.

What I did

  • 11 May: first meeting with mentors and other contributors about issue #252.
  • 15–17 May: rewrote JavaScript from built-in array methods and forEach loops to d3.nest, matching the rest of animint, and documented the approach.
  • 18–19 May: all three CI checks failed on PR #320 because the PR came from my fork. GitHub blocks repository secrets on fork PRs, so PAT_GITHUB arrived empty and animint2pages tests could not authenticate.
  • Pushed the branch to animint/animint2 and opened PR #326. CRAN and R_coverage passed; JS_coverage still failed.
  • 20 May: closed #320 in favor of #326 and updated the polygon-hole test suite.
  • 23–24 May: studied Toby’s draft PR #328, a stronger failing test for holes, and adopted a test-first workflow.

Learnings

Fork PRs and org-branch PRs are not the same CI environment. Secrets, GitHub Pages helpers, and coverage jobs only work when the branch lives in the origin repository. I also learned that “no display on CI” was the wrong diagnosis: both coverage jobs already use chromote, and some failures are flaky enough to retry.

Challenges / notes

JS_coverage still failed after the secrets fix with Chromote / X server warnings. Renderer tests that open a browser are more thorough than compiler-only tests, but they are also more sensitive to CI setup. I waited for mentor guidance before changing tests.yaml.

Next week targets

Port the rendering fix from PR #326 onto the test-polygon-hole branch so the stronger tests in PR #328 pass, then close #326.
