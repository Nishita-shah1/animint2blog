Outcome

On 29 June I opened PR #342 for issue #258. The first C++ was too large. After Toby asked for something closer to 100 lines, I kept grouping in R and moved only the inner compare to common_value_for_group_subset_cpp() (~154 lines).

Context

getCommonChunk() splits compiled plot data so the browser only downloads values that change with a selector. After earlier correctness work, the remaining cost was the inner “is this column constant across chunks?” loop, including NA handling.

What I did

  • Wired Rcpp exports, an options(animint2.use.cpp) R fallback, and 11 unit tests (38 expectations passing).
  • Moved the markdown explanation into vignettes/get-common-chunk-cpp.Rmd.
  • Diagnosed CRAN / coverage CI: committed src/get_common_chunk.o, knitted HTML instead of the .Rmd, and useDynLib being stripped by devtools::document() in the CRAN script.
  • Added R/rcpp-dynlib.R, gitignored build artifacts, and stripped the vignette from the CRAN tarball in build.sh.

Learnings

CRAN CI is a packaging problem as much as a code problem. Object files, knitted vignettes, and NAMESPACE generation can fail a check even when tests pass locally on Windows with Rtools.
